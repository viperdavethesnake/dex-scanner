## Track 2 — Shadow Trader, Phase 1 Investigation (not yet committed)

**Prompt:** `prompts/2026-05-24-shadow-trader.md`  
**Output:** `docs/decisions/SHADOW-TRADER-INVESTIGATION.md`  
**Gate:** Investigation complete. Awaiting user feedback before Phase 2 (design doc).

### What was investigated

1. **Collector service pattern** — documented as the template for `dex-trader` (db.py patterns, error handling, env vars, API layer structure)
2. **`ml.py` model training** — **critical finding: model is never saved to disk**. No `save_model()` anywhere. Must be added before implementation.
3. **`backtest.py` cost assumptions** — 1.5% flat round-trip (gas + fee + slippage); shadow mode's job is to measure whether this holds with real aggregator quotes
4. **Aggregator API surface:**
   - Jupiter v1 (`api.jup.ag/swap/v1/quote`): free key, 1 RPS free tier, `priceImpactPct` for slippage, Solana-only
   - 0x v2 (`api.0x.org/swap/permit2/quote`): free key, 1 RPS, `liquidityAvailable=false` for new thin tokens → fallback required
   - Base fallback chain: Aerodrome Router `0xcF77a3Ba9A5CA399B7c97c74d54e5b1Beb874E43` → Uniswap V3 QuoterV2 `0x3d4e44Eb1374240CE5F1B136Cf395a8eae0e6953`
5. **Trade log schema** — designed `trades` hypertable capturing full lifecycle: intent → quote → fill → exit, with columns for direct backtest-vs-shadow comparison (`cost_delta_pct`)
6. **7 open questions** flagged for Phase 2 design to resolve (signal ingestion method, model save timing, exit price source, Web3 RPC choice, DB isolation, kill switch mechanism, port exposure)

### Key blocker identified

The model is not serialized anywhere. Before Phase 3 (implementation) can begin, `ml.py` must be updated to write:
- `analysis/models/lgbm_base.txt` — LightGBM native format
- `analysis/models/feature_list.json` — ordered feature column names
- `analysis/models/metadata.json` — threshold, train date, AUC
